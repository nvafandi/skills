## Lombok (org.projectlombok:lombok)

Lombok is **not compatible with Quarkus native mode** and is **not managed by the Quarkus BOM**. It may work in JVM mode but fails at native-image build time because Quarkus performs build-time bytecode processing that Lombok's annotation processor does not integrate with.

**Migration strategy: Rewrite Lombok annotations to standard Java / Jakarta / Quarkus equivalents — do NOT keep Lombok.**

| Lombok annotation | Quarkus / Java replacement |
|---|---|
| `@Data` / `@Getter` / `@Setter` | Java records (for DTOs) or explicit getters/setters (for entities) |
| `@NoArgsConstructor` / `@AllArgsConstructor` | Explicit constructors, or Java records for immutables |
| `@RequiredArgsConstructor` | Explicit constructor with dependency injection |
| `@Builder` | Java record (immutable) or manual Builder pattern |
| `@Slf4j` | `org.jboss.logging.Logger` (`Logger.getLogger(...)` or `@Inject Logger`) |
| `@Value` | `record` (Java 16+) |
| `@EqualsAndHashCode` | Auto-generated by Java records |
| `@ToString` | Auto-generated by Java records |
| `@NonNull` | `Objects.requireNonNull(...)` or Jakarta Bean Validation (`@NotNull`) |

> **Why not keep Lombok in JVM mode?** Quarkus has a "closed world" build model. Even if the app compiles in JVM mode with Lombok, the build-time augmentation step (`quarkus-build` / native image) cannot reliably process Lombok-generated code. Mixed Lombok + Quarkus often produces `UnsatisfiedResolutionException` or missing getter/setter errors at runtime. Always rewrite Lombok code as part of the migration — it is a small, mechanical change.

## Reporting / PDF

| Spring Boot / Jasper | Quarkus Replacement |
|---|---|
| `net.sf.jasperreports:jasperreports` | `com.github.librepdf:openpdf` + `com.github.librepdf:openpdf-html` (HTML→PDF) |
| `net.sf.jasperreports:jasperreports-fonts` | `com.github.librepdf:openpdf-fonts-extra` (UTF-8 fonts) |
| `com.lowagie:itext` (Jasper PDF export) | `com.github.librepdf:openpdf` (LGPL/MPL successor of iText 4, same API lineage) |

> **OpenPDF** (https://github.com/LibrePDF/OpenPDF) is an open-source Java library for creating, editing, rendering, and encrypting PDF documents, as well as generating PDFs from HTML.
> - **Maven coordinates:** `com.github.librepdf:openpdf:3.0.5` (latest)
> - **License:** LGPL 2.1 / MPL 2.0 (dual)
> - **Requires:** Java 21+ (2.1.x branch and later)
> - **Package name:** OpenPDF 3.0 uses `org.openpdf` (was `com.lowagie` in the iText 4 lineage)
> - **Modules:** `openpdf` (core), `openpdf-html` (HTML→PDF, fork of Flying Saucer), `openpdf-renderer` (PDF→images), `openpdf-fonts-extra` (UTF-8 Liberation fonts), `openpdf-kotlin`
> - **Not managed by the Quarkus BOM** — the version must be specified explicitly.

## Dependency Syntax by Build Tool

Dependencies listed above use Maven artifact coordinates (`groupId:artifactId`). When working with Gradle build files, use the following mapping:

| Maven | Gradle |
|---|---|
| `<dependency>` (default scope) | `implementation 'groupId:artifactId'` |
| `<scope>test</scope>` | `testImplementation 'groupId:artifactId'` |
| `<scope>runtime</scope>` | `runtimeOnly 'groupId:artifactId'` |
| `<scope>provided</scope>` | `compileOnly 'groupId:artifactId'` |
